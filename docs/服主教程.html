第一章 · 软件总览

软件总览

这是「修改物品制作时间（AdjustCraftingTime）」——一个方舟生存进化服务端 ArkApi 插件。服主在 config.json 里按蓝图路径列出物品并指定制作秒数，玩家制作对应物品 / 图纸时的耗时即按配置改写；未列出的物品完全走原版时长。

🧩

按物品改制作时间

按蓝图路径逐物品指定制作秒数，想调哪个调哪个，支持小数。

⚙️

未命中走原版

没配置的物品完全按游戏原版时长计算，不干扰其他玩法。

🔄

配置热重载命令

控制台 / RCON 执行 Reload 命令，免重启刷新配置。

🛡️

非法条目安全跳过

配置条目写错只输出黄色警告并跳过，不影响其余条目生效。

🛠️

一键编译与部署脚本

工程自带编译（测试版 / 正式版）、一键安装、一键清除脚本。

📝

版本管理脚本

编译正式版脚本可同步更新 Main.cpp 启动横幅与 PluginInfo.json 的版本号。

第三章 · 部署安装

部署安装

以下为拿到编译好的插件后在服务器上的部署步骤。本插件英文名为 AdjustCraftingTime，插件目录、DLL 文件与命令前缀均以此为名。

  1. 确认服务器已安装 ArkApi

    检查服务器目录 ShooterGame\Binaries\Win64\ArkApi\ 是否存在 → 存在则继续；不存在请先安装 ArkApi（最低 3.5）。

  2. 复制插件文件

    把 PluginInfo.json、config.json、AdjustCraftingTime.dll 复制到 ShooterGame\Binaries\Win64\ArkApi\Plugins\AdjustCraftingTime\ → 目录不存在时先创建（工程自带的 一键安装.bat 会自动完成复制与建目录，并可选择同时部署停用副本 AdjustCraftingTime.dll.arkapi）。

  3. 检查配置文件

    打开插件目录下的 config.json，确认内容为合法 JSON → 配置详解见第四章。

  4. 重启服务器

    启动方舟服务器 → 服务器控制台出现「先锋.修改物品制作时间(1.0)」横幅日志即表示插件加载成功；测试版随后还会输出一行「调试输出,测试编码」自检，这行中文显示正常就说明控制台编码匹配（正式版不输出自检行，依据 Main.cpp 的 Load()）。

  5. 验证重载命令

    在服务器控制台或 RCON 执行 AdjustCraftingTime.Reload → 返回 Reloaded config 表示命令可用。

若 config.json 缺失或不是合法 JSON，插件加载时会抛出错误 Can't open config.json（源码 Main.cpp 的 ReadConfig()），插件将无法正常启动。部署前务必确认配置文件存在且格式正确。
编译产物位于工程 Output\AdjustCraftingTime\ 目录；首次使用编译脚本前需先运行 环境变量.bat 设置 ASE_API（用户级永久环境变量，重启命令行 / VS 后生效）。

第四章 · 配置详解

ConsoleEncoding 控制台编码

什么意思：控制插件往服务器控制台输出文字时用的编码。不同版本 ArkApi 的服务器控制台编码不同（3.54 为 GBK/ANSI，3.55 为 UTF-8），编码不匹配时控制台中文会乱码。本插件输出前会按这个配置决定是否把 UTF-8 转成 GBK（Main.cpp 的 应用控制台编码配置，插件日志模块 h/日志.h 的自动输出系列同受其控制）。

兜底值：auto（配置缺失或值非法时都按 auto 处理，非法值会在控制台提示一行黄色警告）

{
  "ConsoleEncoding": "auto"
}

怎么修改：可选值共三个（大小写不限）：

取值效果
auto自动探测：控制台代码页为 936 时转 GBK 输出，否则按 UTF-8 原样输出。3.54 / 3.55 服务器都不用改配置，推荐保持默认
gbk强制输出前转 GBK（等同旧版行为；写 ansi 也可以）
utf8强制 UTF-8 原样输出（写 utf-8 也可以）
改完不用重启：控制台 / RCON 执行 AdjustCraftingTime.Reload 即可热生效（编码解析在每次读取配置时进行）。
第四章 · 配置详解

List 制作时间列表

什么意思：List 是制作时间条目的数组，每条描述一个物品。玩家制作该物品（含用图纸制作产物）时，插件按 Blueprint 匹配物品蓝图路径，命中即把制作耗时改为 Time 指定的秒数——是直接替换原版时长，不是倍率；未命中的物品完全走原版逻辑。

兜底值：空表（List 缺失、不是数组或条目全部非法时，不修改任何物品的制作时间，全部走原版时长）

{
  "List": [
    { "Blueprint": "Blueprint'/Game/PrimalEarth/CoreBlueprints/Items/Structures/Misc/PrimalItemStructure_AnvilBench.PrimalItemStructure_AnvilBench'", "Time": 5.0 },
    { "Blueprint": "Blueprint'/Game/PrimalEarth/CoreBlueprints/Items/Consumables/Base/PrimalItemConsumable_Berry.PrimalItemConsumable_Berry'", "Time": 1.0 }
  ]
}

怎么修改：按下表逐条填写，要调整几个物品就写几条；同一物品出现多条时以最后一条为准。改完执行 AdjustCraftingTime.Reload 立即生效。

配置键类型缺失/非法时含义与取值
List[].Blueprint字符串整条跳过，控制台黄色警告物品蓝图路径，形如 Blueprint'/Game/.../物品.物品'，结尾不带 _C，须与游戏内路径完全一致（保留外层 Blueprint'...' 引号）
List[].Time数字整条跳过，控制台黄色警告制作耗时秒数，支持小数（如 0.5、12.5），建议填正数
蓝图路径可从方舟 Wiki 物品页（Blueprint path）、其他插件的配置文件中获取，但 Wiki 上的路径通常以 _C 结尾——填入本插件配置时须去掉末尾的 _C（插件内部匹配用的路径不带它）。写错路径不会报错——只是永远匹配不上，物品保持原版时长，部署后留意实际制作耗时即可验证。

第五章 · 命令用法详解

AdjustCraftingTime.Reload 命令详解

作用：让插件重新读取 config.json。改完配置不想重启服务器时用它，立即生效。

AdjustCraftingTime.Reload
参数必填缺省值说明
无参数——本命令不带任何参数（源码 Main.cpp 的 ReloadConfig / ReloadConfigRcon）

示例一（服务器控制台）：AdjustCraftingTime.Reload——插件立即重读 config.json，制作时间调整即刻生效，控制台返回 Reloaded config。

示例二（RCON 远程）：AdjustCraftingTime.Reload——人在服务器外用远程管理工具连 RCON 发同一条命令，效果相同，改配置不用回到服务器前。

反馈：成功时绿色提示 Reloaded config；配置文件缺失或 JSON 损坏时红色提示 Failed to reload config，同时错误详情写入日志（源码原文）。命令名固定为 AdjustCraftingTime.Reload；只能在控制台 / RCON 使用，不是游戏内聊天命令。

第六章 · 常见问题

常见问题

控制台中文乱码（方块/问号）？
先试这个：看插件启动时自检输出的「调试输出,测试编码」行（仅测试版输出）——这行中文显示正常就说明编码匹配，无需处理；若这行乱码，保持 ConsoleEncoding 为 auto（插件会按服务器控制台代码页自动选择编码）并执行 AdjustCraftingTime.Reload；仍乱码再按 ArkApi 版本显式指定——3.54 服务器设 gbk、3.55 服务器设 utf8。
插件没加载，控制台提示 Can't open config.json？
先试这个：检查 ArkApi\Plugins\AdjustCraftingTime\config.json 是否存在、文件名拼写是否正确；存在则用 JSON 校验工具检查格式（多逗号、缺引号都会导致解析失败）。
改了 config.json 但没生效？
先试这个：在控制台或 RCON 执行 AdjustCraftingTime.Reload 热重载；若提示 Failed to reload config 说明新配置格式有错，按报错修正后重试。仍不生效则重启服务器。
配置了物品，制作时间却没变？
先试这个：①检查蓝图路径写法——结尾不带 _C、保留外层 Blueprint'...' 引号（写法见第四章 List 小节）；②执行 AdjustCraftingTime.Reload 并留意控制台有无「List 存在非法条目」黄色警告，有则按警告修正对应条目；③同一物品写了多条时以最后一条为准，检查是否被后面的条目覆盖。
配置文件放哪里？
插件目录固定为 ShooterGame\Binaries\Win64\ArkApi\Plugins\AdjustCraftingTime\config.json，与 AdjustCraftingTime.dll 同目录。
配置改坏了怎么恢复？
先试这个：用修改前的备份覆盖回去；没有备份时，参照本教程第四章的示例片段重建，保证 JSON 语法完整（逗号、引号齐全）。
怎么临时停用插件？
把插件目录下的 AdjustCraftingTime.dll 改名为 AdjustCraftingTime.dll.arkapi（ArkApi 不加载该后缀），重启服务器即可停用；改回 .dll 恢复。工程的 一键安装.bat 也支持部署停用副本。
编译脚本报错找不到 ArkApi？
先试这个：运行工程目录下的 环境变量.bat 设置 ASE_API 环境变量指向 ServerAPI 目录（默认探测 D:\ASE\ServerAPI），设置后重新打开命令行 / VS 再编译；并确认 ServerAPI 已运行其 build.bat 生成 ArkApi.lib。
